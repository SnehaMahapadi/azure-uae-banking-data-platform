# Data dictionary

All data is **synthetic**. Names, merchants, IDs and e-mail addresses are randomly generated (e-mails use `example.com`). Timestamps are UAE local time (Gulf Standard Time, UTC+4). The base currency is AED, and AED is pegged to USD.

Generated by `scripts/generate_dataset.py` (seed 7). Same seed gives the same data.

## customers (`raw/customers/customers_initial.csv`) · 5,000 rows · CSV
Grain: one row per customer (initial snapshot, January 2026). In the lake: `landing/raw/customers/`.

| Column | Notes |
|---|---|
| customer_id | Key. `C000001` format |
| first_name, last_name | Random |
| date_of_birth | `YYYY-MM-DD` |
| gender | `F` / `M` |
| nationality | UAE, India, Pakistan, Philippines, Egypt, UK, Jordan, Bangladesh, Other |
| emirate | Seven emirates |
| segment | Retail / Premium / SME. **Changes over time** (see customer_changes) |
| kyc_status | Verified / Pending / Expired |
| onboarding_date | `YYYY-MM-DD` |
| email | Fake, `@example.com` |

## customer_changes (`raw/customers/customer_changes.csv`) · 750 rows · CSV
Grain: one row per attribute change during 2026. Used in **Phase 3 (SCD Type 2)**. Not uploaded in Phase 0.

| Column | Notes |
|---|---|
| customer_id | FK to customers |
| attribute | `segment` or `emirate` |
| old_value, new_value | Before and after |
| effective_date | `YYYY-MM-DD`, between Feb and mid-Sep 2026 |

## accounts (`raw/accounts/accounts.csv`) · 7,834 rows · CSV
Grain: one row per account. Every customer has a Current account, and many also have Savings, Credit Card or Wallet.

| Column | Notes |
|---|---|
| account_id | Key. `A00000001` format |
| customer_id | FK to customers |
| account_type | Current / Savings / Credit Card / Wallet |
| currency | AED (about 90%), USD, EUR |
| open_date | `YYYY-MM-DD` |
| status | Active / Dormant / Closed |
| branch_code | `BR001` to `BR040` |

## merchants (`raw/merchants/merchants.jsonl`) · 600 rows · JSON Lines (nested)
Grain: one row per merchant.

| Field | Notes |
|---|---|
| merchant_id | Key. `M00001` format |
| name | Fictional |
| mcc | Merchant category code |
| category | 14 categories (Grocery, Restaurants, Fuel, Electronics, Airlines and more) |
| location | **Nested object**: `emirate`, `city`. Flatten in silver. |
| risk_tier | Low / Medium / High |
| onboarded_date | `YYYY-MM-DD` |

## fx_rates (`raw/fx_rates/fx_rates.csv`) · 819 rows · CSV
Grain: one row per day per currency (1 Jan to 30 Sep 2026).

| Column | Notes |
|---|---|
| rate_date | `YYYY-MM-DD` |
| currency | USD, EUR, GBP |
| rate_to_aed | AED per 1 unit of currency |

## transactions (`raw/transactions/month=2026-MM/transactions_2026_MM.csv`) · about 222,600 rows over 9 files · CSV
Grain: one row per transaction event. One file per month, January to September 2026.

| Column | Notes |
|---|---|
| transaction_id | Intended key. **Not guaranteed unique in the raw files.** |
| account_id | FK to accounts |
| merchant_id | FK to merchants. Legitimately empty for transfers, ATM withdrawals and wallet top-ups |
| txn_timestamp | UAE local time |
| txn_type | PURCHASE / BILL_PAY / TRANSFER_OUT / ATM_WITHDRAWAL / REFUND / WALLET_TOPUP |
| channel | POS / ECOM / WALLET / MOBILE_APP / BRANCH / ATM |
| amount | In the transaction currency |
| currency | Transaction currency |
| country | `AE` for most, some foreign |
| status | SUCCESS / DECLINED / REVERSED |
| decline_reason | Only when status is DECLINED |
| fraud_flag | 0/1 label (simulated). Higher likelihood for foreign, night-time and large transactions |

## Data-quality problems

The transaction files contain realistic problems on purpose, because Domain 2 tests that you can find and handle them. **Find them yourself first.** The answer key is `docs/dq-answer-key.json` (counts per month). Don't open it until you've finished Phase 2.

## Where each table is used

Phases are defined in [`build-plan.md`](build-plan.md).

| Table | Phases |
|---|---|
| customers, accounts, merchants, fx_rates | 1 (ingest), 2 (bronze, silver), 4 (gold dimensions) |
| customer_changes | 3 (SCD2) |
| transactions (monthly files) | 1 (January), 2 (clean), 3 (February to September, incremental), 4 (fact table), 5 (orchestration) |
| Simulated payment events (script added in Phase 6) | 6 (Azure Data Explorer, KQL) |
